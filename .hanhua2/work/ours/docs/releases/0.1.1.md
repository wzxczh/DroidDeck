# SteamDeck 0.1.1

**一个补丁版本，主要关于 0.1 无法做到的两件事：更换驱动，以及告诉你出了什么问题。** 直接安装在 0.1 之上——相同密钥、相同运行时，无需重新下载。

这里的一切都来自三台设备一天的反馈，这就是为什么其中这么多内容是关于能够*看到*故障，而不是新功能。

---

##  图形驱动 - 主屏幕上的新按钮

两个列表，因为一个 zip 无法服务另一个：

- **Linux 运行时驱动** - 运行时*内部*一切渲染所用的 glibc Turnip：Steam 客户端的界面、它启动的每个游戏，以及桌面模式下桌面上的每个程序。导入 `-Linux` Turnip zip；Android 或 `-Wayland` zip 会被拒绝并给出原因，而不是变成黑屏。选择是**按模式**的，因此 Steam 和桌面可以运行不同的构建。运行时内部没有任何东西被修改——会话被指向导入的驱动，而移除或不可读的导入会回退到运行时自己的 Turnip。
- **显示驱动 (Android)** - 应用合成器用来将帧放到面板上的 bionic Turnip。*Auto* 在两个捆绑构建之间保持 GPU 选择；也可以选择导入的 AdrenoTools zip。它在应用完全关闭并重新打开后生效，因为合成器每个进程只加载一次其驱动。

这就是驱动修复现在如何到达已安装运行时，而无需约 790 MB 的重新下载。

 **已在设备上验证：** 导入的 Mesa 26.3.0（Vulkan 1.4.363）glibc Turnip 绘制整个 Steam 会话——gamescope、客户端、其 UI 助手和 Xwayland 全部运行在它上面——并在合成器中使用导入的 Android Turnip 替代捆绑构建。

###  Adreno 710 / 720 / 722

0.1 在这些设备上完全无法启动：Mesa 没有它们的条目，会话在 `device (chip_id = 7010000, gpu_id = 710) is unsupported` 处死亡。现在有了一条路径——从 Banners-Turnip 的 `v26.3.0-20260921-r3` 或更新版本导入 `Turnip-…-710-720-Test.zip` 作为**显示驱动**，导入 `…-710-720-Test-Linux.zip` 作为 **Linux 运行时驱动**。这些 GPU 还需要 sysmem 渲染，当应用看到选择了该驱动时会自行设置。

 **未在真实硬件上验证。** 还没有人在 710 上运行过此运行时。如果你有一台，会话文件夹就是要发送的东西。

##  声音和麦克风

**游戏 DirectAudio** 将 Wine 的音频驱动*替换到客户端启动的游戏内部*，改为通过 socket 直接与 Android 对话——中间没有 PulseAudio，也没有重采样。客户端本身无论如何都保留 PulseAudio；它是一个原生 Linux 程序，没有其他发声方式。它只与 Wine 11 Proton（Valve 的 ARM64 构建、GE-Proton、proton-cachyos）配对，在其他任何东西上都保持关闭而不是播放静音，并在日志中说明。

**麦克风** 是它自己的开关：relay 助手在应用自己的 uid 下打开 Android 的输入流——录制权限正是针对该 uid 检查的——PulseAudio 将其作为 **DirectAudioMic** 暴露给客户端，用于语音聊天。关闭时，会话中没有任何东西可以录制，Android 的指示器保持关闭。

两者都在主屏幕的 **Audio** 下，都默认关闭，都在下次会话启动时生效。启用 DirectAudio 后游戏的首次启动仍然使用 Proton 自己的音频——驱动在该游戏的 prefix 中被命名，而该 prefix 直到那时才存在——第二次使用 DirectAudio。

 已构建并接线；麦克风只有在修复捆绑的 PulseAudio 后才到达 `DirectAudioMic`（0.1 在 13.0 守护进程旁边附带了一个 17.0 构建的模块，因此它永远无法加载）。将语音视为准备测试而不是已证明。

##  Steam 的 overlay，以及抢你登录的应用

两个偏离正常 Steam 启动的地方，都通过移除而不是绕过来解决。

overlay 过去从每个游戏中剥离，因为它挡在控制器读取器前面。那是一个顺序问题——interposer 现在先行，overlay 按 Valve 的意图加载。Valve 发布的启动与这里运行的内容之间的每一个差异，都是此运行时否则必须解释的差异。

而且同一部手机上的另一个 Steam 客户端会在每次登录后几秒钟将此客户端登出。应用现在在会话开始时请求 Android 停止它，并说明这一点。如果那个应用通过启动接收器自行重启，后台停止是一场它能赢的竞赛——如果客户端持续登出，卸载另一个。

##  性能和会话修复

主屏幕上的 **Performance**，全部默认关闭，全部在下次会话启动时生效：

| | |
|---|---|
| **Steam 客户端核心** | Steam 将其自己的界面固定到它选择的核心子集——在一台设备上是八个中的五个，排除了最快的——这适合正在运行的游戏，但当客户端是全部时会使菜单迟缓。覆盖它会将客户端、其 UI 助手和 gamescope 固定到你勾选的核心，每隔几秒重新应用，因为 UI 不断生成继承 Steam 选择的助手 |
| **游戏核心** | 游戏可以运行的核心，通过 `taskset` exec 它来应用，因此每个线程从其第一条指令继承掩码 |
| **跳过 Steam 的 xalia 助手** | `xalia` 是 Proton 为手柄导航启动的 x86 Windows 程序。在某些设备上，它的系统调用被拒绝，方式它无法应对，会话在 Big Picture 出现几秒后死亡。如果会话无法保持运行，请打开此选项 |
| **无 seccomp 运行 proot** | proot 通常让大多数系统调用不被跟踪运行，这是它大部分速度的来源。某些内核处理得很差，拒绝明显存在的调用。这改为跟踪一切：更慢，但正确 |
| **Turnip：sysmem 渲染** | 用于看起来故障或缓慢的 Adreno 8xx，并且在 710/720/722 上是必需的 |
| **Zink：惰性描述符** | 客户端的菜单通过 Zink 绘制；当游戏快而菜单慢时，这是首先要尝试的 |

加上 `Download/steamdeck-env`，一个 `KEY=VALUE` 行文件，添加到会话的环境，用于原本每次尝试都需要构建的实验。

##  值得发送的日志

这是将节省最多时间的更改。每个会话现在获得**自己的文件夹**：

```
Download/SteamDeck/session-20260921-161256/
    device.txt     这个设备是什么，以及会话运行时的每个设置
    network.txt    链路、给运行时的 DNS，以及它意味着什么
    app.log        应用本身决定和报告的内容
    crash.log      Android 的崩溃缓冲区，在会话结束时的状态
    audio.log      PulseAudio 守护进程和 DirectAudio relay 助手
    session.log    guest 会话：proot、gamescope、客户端自己的输出
    wayland.log    合成器 - 它呈现了什么，以及多快
    steam.log + steam/   客户端自己的日志                  (Steam 模式)
    desktop.log    labwc、面板及其上的程序      (桌面模式)
```

`device.txt` 在会话开始前写入，因此一个在第一秒就死亡的会话仍然说明它运行在什么上：型号、SoC、Android 和内核、核心及其上限、RAM、KGSL 命名的 GPU、面板、**会话每一半选择了哪个驱动**，以及生效的每个开关。`crash.log` 是*系统*杀死的会话留下唯一痕迹的地方。

**凭据被清理，不收集任何可识别信息。** Steam 的日志在进入时逐行过滤——会话令牌、机器认证 GUID、WebAPI 密钥、Guard 代码和电子邮件地址被替换，SteamID 被掩码为最后四位数字，以便行仍然相关。`loginusers.vdf`、`config.vdf` 和 `ssfn` 文件绝不复制。没有序列号、没有设备或广告 id、没有账户名、没有网络名。**会话文件夹就应该按原样附加到报告。**

---

##  如果 Steam 死了而日志中什么都没有

那通常不是 Steam。**Android 12 及更高版本会在应用为自己启动的额外进程超过几个时杀死它们**，而一个会话由几十个组成——proot、gamescope、Xwayland、客户端及其助手、Wine、FEX。如果该功能保持开启，操作系统会结束会话，我们的日志不会说明原因，因为会话中没有任何东西这样做。

一些手机在开发者选项中将其暴露为 **“限制子进程”** 开关——将其关闭。否则，每台设备一次：

```sh
adb shell settings put global settings_enable_monitor_phantom_procs false
```

`device.txt` 记录你的手机报告的内容，Performance 对话框在未禁用时会说明。

## 0.1 仍然成立

受 VAC 保护的游戏报告不安全。仅发布 Linux 版本的游戏不会启动——改为安装 Windows 版本。桌面在软件中合成，Firefox 的子进程沙箱在那里关闭。没有 Switch 模拟器。模拟器包可以安装，但尚未有任何带游戏运行过。

如果游戏启动并立即死亡，请检查客户端中的 **属性 → 兼容性**：指向 ARM64 Proton 的游戏需要该 depot 已完成下载，会话日志在未完成时会清楚地说明。
