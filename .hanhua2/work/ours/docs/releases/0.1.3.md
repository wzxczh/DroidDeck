# SteamDeck 0.1.3

**一件事，而且是欠下的：客户端的网络页面可以工作了，并且它的连接指示器说实话。** 直接安装在 0.1.2 之上；相同密钥、相同运行时，无需重新下载。

---

##  设置 → 互联网可以工作，并且标题显示连接

Steam 客户端在 NetworkManager 上构建其网络页面和连接指示器，并在启动时在系统总线上寻找一个。此运行时两者都没有，因此页面在标题下停止并显示 *"StartScanningForNetworks is not a function"*，即使下载正在运行，标题也显示无连接。一位 Odin 2 用户第一天就报告了完全相同的问题。

会话现在启动一个小型系统总线和**一个替身来应答 NetworkManager**。它报告真实情况，仅此而已——一个连接，在 Android 有出口路由时处于启动状态——并拒绝它不能做的事情，因为此运行时中没有任何东西可以扫描或加入网络。会话日志在工作时显示 `network: system bus up, NetworkManager stand-in running`。

替身和总线配置都在每次启动时来自应用，因此已安装的运行时无需重新下载即可获得；`dbus-daemon` 和 `python-gi` 已经在其中。

**替身是 maxjivi05 的**，为 WinNative 编写，此后由 Bannerlator 携带；此应用是三者中唯一没有它的。应得的归功，并向 Odin 2 报告者道歉，他被告知这是表面问题且未修复，而它在上游已经修复了好几天。

##  运行时与其来源的对比状态

通过此版本，独立版本的运行时脚本与 Bannerlator 的持平，并且其沙箱 shim 与 Max 当前分支的行为逐字节相同——今天逐文件检查过；每个差异都是故意的重命名或归属头。他那边剩下而这里没有的是一个功能，而不是修复：从原生客户端启动 Epic 游戏。

##  如果客户端死了而日志中什么都没有

Android 12 及更高版本会杀死应用为自己启动的额外进程，而一个会话由几十个组成。一些手机在开发者选项中有 **“限制子进程”** 开关——将其关闭。否则，每台设备一次：`adb shell settings put global settings_enable_monitor_phantom_procs false`。每个会话文件夹中的 `device.txt` 记录你的手机报告的内容。
