# SteamDeck 0.1.2

**一个修复版本。0.1.1 会在你离开会话时挂起应用——这已修复，并且本来就能解释它的两行日志也已加入。** 直接安装在 0.1.1 之上；相同密钥、相同运行时，无需重新下载。

---

##  离开会话可能会挂起应用

0.1.1 在会话停止时在主线程上收集会话日志——复制合成器的日志、逐行清理客户端每个日志，然后等待 Android 的崩溃缓冲区。在桌面会话上，这大约是四秒半的冻结应用，Android 将其作为无响应结束。收集现在在它自己的线程上进行。

这是由 0.1.1 自己的日志引入的，这就是本次发布的全部原因。

`crash.log` 在 0.1.1 中也错了两处：它等待在另一个线程上到达的输出，因此每次都声明缓冲区为空；并且它在本该是退出状态的地方打印了进程 id。它现在等待 dump 完成，并说明三种情况中的哪一种发生了——无法启动、未完成，或确实没有任何东西崩溃。

##  缺失的两行日志

两者都来自追查一个真实报告：一个从 Steam 菜单返回后变成屏幕角落小盒子的游戏。

- **`changed its frame size: 1920x1080 -> …`** - 一个以新尺寸提交帧的窗口重建了其 swapchain，而这正是从合成器角度看游戏缩小的样子。尺寸以前在日志中无处可寻，必须从截图中猜测。
- **`renamed "Steam Big Picture Mode" -> "Flat-Out"`** - gamescope 保持一个窗口并在游戏占据屏幕时重命名它。那是静默的，因此日志显示一个窗口在它从未被记录为打开的名称下*关闭*了，这看起来像缺失事件，实际上是重命名。

##  与应用匹配的 README

README 按功能编写顺序每个功能长出一节，而描述整体的部分已经落后。功能账本现在覆盖驱动、音频、核心、会话修复和日志，每个都有诚实的状态——包括用平实的语言说明几个设置了它们声称的东西但从未在硬件上测量过。架构图显示音频 relay 和两个 Turnip 槽位。会话日志文件夹有自己的章节。并且 **Installing** 现在提到决定会话是否能保持运行的那个 Android 设置。

你可以导入并按模式选择的图形驱动 · Steam 的 overlay 恢复，竞争客户端被要求停止 · 游戏 DirectAudio 和麦克风 · 客户端和游戏核心掩码 · 四个会话修复（xalia、无 seccomp 的 proot、Turnip sysmem、Zink 惰性描述符）· `Download/steamdeck-env` · 每个会话一个日志文件夹，凭据已清理且不收集任何可识别信息 · 通过导入驱动为 Adreno 710 / 720 / 722 提供路径。

##  如果客户端死了而日志中什么都没有

那通常不是客户端。**Android 12 及更高版本会杀死应用为自己启动的额外进程**，而一个会话由几十个组成。一些手机在开发者选项中有 **“限制子进程”** 开关——将其关闭。否则，每台设备一次：

```sh
adb shell settings put global settings_enable_monitor_phantom_procs false
```

每个会话文件夹中的 `device.txt` 记录你的手机报告的内容，Performance 对话框在未禁用时会说明。
