# SteamDeck 0.1

**Valve 的原生 ARM64 Linux Steam 客户端，运行在 Android 手机或掌机上——现在旁边还有一个 Linux 桌面。** 没有 Wine，客户端本身也没有 x86 转译：它是作为 ARM 代码运行的 ARM 代码，在 gamescope 下，通过应用内 Vulkan 合成器呈现到你的屏幕上。它启动的 Windows 游戏经过 Valve 自己的 ARM64 Proton，FEX 就在这里发挥作用。

这是首个版本。一个屏幕，一个按钮：安装运行时，按 **Play**，Big Picture 出现。

>  **早期软件。** Steam 客户端和桌面都已在真实硬件上端到端运行过，但这是 0.1 版，其中很大一部分只在一两台设备上验证过。如果某些内容尚未测试，本页会说明，而不是暗示它可用。

# 它做什么

##  Steam 客户端，原生

登录、浏览你的库、安装并游玩。客户端在首次使用时从设备上 Valve 自己的清单获取——**此处不再分发任何 Valve 软件**。Windows 游戏通过 Valve 提供的 ARM64 Proton 构建运行，由 Steam 自身下载。

 **已在设备上验证：** 登录、自动获取 Proton ARM64、从商店安装并启动游戏——*FlatOut* 以 144 Hz 渲染。

##  Linux 桌面

应用可以启动的第二样东西：**LXQt on labwc**，在同一个会话和同一个合成器中，并为 X11 程序提供 Xwayland。其上的所有内容都按需从运行时旁边托管的目录下载，因此应用保持小巧。

| 包 | 它带来什么 |
|---|---|
| **桌面** (406 MB) | labwc、LXQt 面板、文件管理器、终端、文本和图像查看器、Firefox、mpv |
| **模拟器** (694 MB) | PPSSPP 和 RetroArch 带 28 个核心，外加 ScummVM、DOSBox、Mednafen、Snes9x |
| **RPCS3 · DuckStation · melonDS** | PS3、PS1、DS——这些项目自己的 ARM64 构建 |
| **PCSX2 · Dolphin · Cemu** | PS2、GameCube/Wii、Wii U——**这三个上游都没有 ARM64 Linux 构建**，因此它们针对运行时使用的同一 glibc 从源代码编译 |

它们之间包括：PS1、PS2、PS3、PSP、GameCube、Wii、Wii U、N64、SNES、NES、Game Boy/Color/Advance、DS、Genesis、Dreamcast、Saturn、PC Engine、街机和 DOS。

 **已在设备上验证：** 桌面启动，面板、壁纸和文件管理器都出现，以面板原生分辨率，并且 Firefox 以 93 fps 浏览实时互联网。
 **尚未在设备上运行：** 模拟器本身。它们能构建、发布和安装；尚未有任何一个带游戏启动过。

##  帧生成

在真实帧之间生成额外帧，**在应用的合成器内部**，作用于 gamescope 的最终输出——因此它适用于任何游戏，运行时无需改动。**Win-FG** 内置。**LSFG** 使用你自己那份 Lossless Scaling 的着色器链：在此应用中的 Steam 客户端里安装它，应用会从运行时的 Steam 库中读取其 `Lossless.dll`（作为数据解析，绝不执行；其中没有任何内容被再分发）。在主屏幕上选择引擎和 2×/3×/4×——立即生效，包括游戏中途。

 **已在设备上验证：** LSFG 2× 在 *FlatOut* 中生成——观察到 30 → 61、60 → 118 和 61 → 123 fps，屏幕读数显示 `base → generated`。

##  控制、指针和键盘

物理控制器作为合成的 **Xbox 360 手柄**重新发布到会话中——这是 SDL 和 Steam 有映射的身份。没有连接任何设备时，会出现一个**屏幕手柄**并写入相同的环，因此客户端无论如何都看到一个手柄；连接控制器后屏幕手柄消失，拔掉它又回来。

应用绘制指针。在桌面上，触摸是**触控板**：在任何地方拖动，指针从当前位置移动，点击即点击，一根手指按住时第二根手指点击（或双指点击）为右键点击，双指滚动，按住再拖动为拖动。在 Steam 中，触摸是**直接**的——指针跳到你的手指下。USB 或蓝牙鼠标按自身工作。

抽屉中的 **Keyboard** 将软键盘覆盖在会话上，转换为本来会键入的按键——包括 Shift，因此大写字母和符号行按原样到达。

 **尚未在设备上测试：** 软键盘。

##  网络

会话直接使用手机的网络——proot 不创建网络命名空间，因此 **IPv4 和 IPv6 都直接通过**——并且每次链路变化时，应用都会从活动网络自己的 DNS 服务器写入运行时的 `/etc/resolv.conf`。

 **已在设备上验证：** 从会话内部通过 IPv4 和 IPv6 进行名称解析和 HTTPS 获取，以及 Firefox 加载实时页面。

##  离线启动 Steam

主屏幕上的 **Start offline** 在不登录 Valve 的情况下启动客户端。已安装的游戏可以启动；Proton 和帧生成本来就是本地的。它位于主屏幕而不是抽屉中是有原因的：客户端在启动时*一次*读取控制此行为的键，因此在会话中途更改它直到下次启动才会生效。如果没有之前成功登录，按钮会说明这一点并保持禁用。

 **尚未在设备上测试。** 具有始终在线 DRM 的游戏将无法离线启动，并且离线时无法安装或更新任何内容。

##  兼容性工具

**Compatibility tools** 安装 **GE-Proton** 或 **proton-cachyos**——原生 ARM64 构建——放在 Valve 提供的 ARM64 Proton 旁边。运行时的 registrar 在下次会话启动时获取请求的构建，将其修补绕过 pressure-vessel，然后它会出现在 Steam 中任何游戏的属性 → 兼容性下。

 **尚未在此应用中测试。**

##  后台、前台和抽屉

会话属于**前台服务**，而不是 activity，因此离开 Big Picture 不会结束它：可感知优先级、部分唤醒锁以便 guest 的线程继续运行，以及高性能 WiFi 锁以便后台下载不会被限制到零。通知是静默的，并将会话带回。

**Back 打开抽屉：** 性能 HUD、帧生成、屏幕控件（自动/始终/从不）、触摸模式、显示形状、*发送到后台* 和 *停止会话*。会话只在你说结束时结束。

##  可折叠设备和异形面板

主屏幕会缩放到给定的任何面板和密度。在会话中，显示形状要么是面板自身的，要么是固定的 **16:9**——可折叠设备上的默认值，因此在会话中途打开或关闭设备只会改变黑边，绝不改变画面。

 **已在设备上验证：** 在会话中途展开和折叠 Fold。

# 安装

下载下方的 APK 并安装。首次启动时它会下载 Linux 运行时（约 790 MB，一次）。然后按 **Play**。

**如果 Bannerlator 已安装**，运行时镜像是同一个——README 展示了如何用 root 将其复制过来并完全跳过下载。此后两个应用保持独立：独立的 Steam 安装、独立的登录、独立的游戏。

**要求：** 一台带 Adreno GPU 的 arm64 Android 设备（合成器加载 Turnip 驱动），以及在任何游戏之前为运行时预留大约 3 GB 空间。

# 已知限制

- **桌面在软件中合成。** wlroots 在真实 DRM 渲染节点上通过 gbm 分配，而 Adreno 替身不是，因此 labwc 运行在 pixman 上。程序仍然通过 Vulkan 和 Turnip 自行到达 GPU——只是桌面自己的合成在 CPU 上。
- **Firefox 的子进程沙箱被关闭**，因为 seccomp 和命名空间沙箱无法在 proot 下设置，否则其标签页会崩溃。这是隔离性的真实降低：在此浏览应被视为比在普通桌面上保护更少。
- **更改显示形状在下次会话生效**，不是立即——gamescope 在启动时固定其显示尺寸。
- **没有 Switch 模拟器。** Eden 的仓库在二月被下架，没有可镜像或构建的内容。
- PS3 (RPCS3) 和 Wii U (Cemu) 即使在桌面硬件上也很吃性能；只期望轻量游戏。
